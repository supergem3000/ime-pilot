# IME Pilot

一个自动切换输入法中英文的桌面工具。主体使用 Go + Wails v3，目标支持 Windows 和 macOS。

## 三部分怎么分工

| 部分 | 做什么 |
| --- | --- |
| 接管程序插件 | 针对 IDEA、VS Code 等程序，监听内部事件，自行决定什么时候切中文或英文 |
| 后台常驻主体 | 提供设置界面和托盘，管理插件连接与接管关系，处理普通程序的窗口切换规则 |
| 输入法控制器 | 适配不同系统和输入法，实际执行中英文切换，并确认结果 |

插件告诉主体目标进程和切换模式，主体确认目标仍在前台，再交给控制器执行：Windows 校验 PID 与 HWND，macOS 只校验前台应用 PID。主体和控制器在同一个进程里。

插件的行为设置放在插件中；普通程序规则和输入法执行设置放在主体中。接入 IdeaVim 不需要修改用户的配置文件。

## 接管以后怎么工作

- 插件注册时声明自己的 ID、名称、版本、运行实例，以及要接管的程序。
- Windows 用可执行文件名或完整路径匹配，macOS 用应用 Bundle ID 匹配。接管覆盖全部匹配实例和窗口。
- 接管期间，主体的普通应用规则暂停执行，界面显示“被 XXX 插件接管”。不需要先添加或勾选应用规则。
- 插件全权决定窗口聚焦、Vim 模式等事件的行为。主体不接收这些事件细节，也不要求声明观察能力。
- 同一个插件可以有多个运行实例；只要还有有效实例覆盖，接管就继续。不同插件接管同一程序时，拒绝后来的冲突申请。
- 全局暂停对插件和普通规则都有效，暂停不解除接管。

例如：IDEA 插件决定退出 Insert 时切英文；浏览器没有插件，就按主体中的窗口切换规则处理。

每条普通应用规则可设置进入应用时“切中文”或“切英文”，通过启用开关决定是否执行。停用时保留目标模式，重新启用后继续使用。修改后自动保存，下次进入应用生效。新规则默认切英文；插件接管期间保留这些设置，断开后恢复使用。

“其他应用”可设置切中文、切英文或不切换，默认不切换。只作用于未被插件接管、也没有单独规则的应用；已添加但停用的规则仍不切换。应用列表直接显示完整程序路径（macOS 显示 Bundle ID）。

## 插件只需要四个接口

插件与主体通过本机 HTTP/JSON 通信，无需互联网。

具体字段与错误处理见 [插件通信协议](protocol/README.md)。

| 接口 | 插件发送什么 | 主体返回什么 |
| --- | --- | --- |
| 注册 registerPlugin | 插件基本信息、运行实例 ID、接管程序列表 | 会话 ID、续期要求、暂停状态 |
| 续期 renewSession | 会话 ID | 续期结果、暂停状态 |
| 切换 setInputMode | 会话 ID、中文或英文、目标进程（Windows 另带 HWND） | 已切换、已是目标状态，或失败原因 |
| 注销 unregisterPlugin | 会话 ID | 注销结果 |

每个请求用 requestId 标识并防止重复执行，响应体统一为 code、data、message，通过对应的 HTTP 请求关联。插件串行发送切换请求，发送前确认任务仍有效，不积压旧事件；主体限制排队时间并在执行前核实前台目标。插件不传 Vim 模式、输入文字或按键内容，超时不自动重发旧切换。

插件正常退出时注销，立即解除对应接管；突然崩溃则等租约到期。初定每 5 秒续期，15 秒未续期视为断开，单次 HTTP 失败不会立即交还。

主体用 sessionId 校验会话；会话不存在或到期时返回 session_expired，插件重新注册。主体重启后清空会话，不恢复在线接管。

最后一个覆盖实例断开后，恢复原应用规则，等下一次窗口切换触发，不立即补切当前窗口。重连也不补发旧事件。

## 输入法怎么切

Windows 提供三种方案：“模拟 Shift 按键”只读取 IMM 状态，按需发送一次 Shift 并回读，使用前需在目标应用选中豆包并保持 Shift 中英文切换设置；IMM 控制当前输入法内部中英文状态（实测微软拼音）；“输入法与键盘布局切换”可选择具体中文输入法（如豆包、微软拼音）和英文布局，配置完整后自动保存。具体输入法使用纯 Go 调用 Windows TSF，配合目标窗口的输入语言切换，不注入 DLL；TSF 激活范围覆盖当前桌面，会影响其他应用。该路径只报告调用完成，无法回读确认目标应用的具体输入法，需核对实际输入。仅配置键盘布局时继续按目标线程 HKL 切换和回读。HKL 与 TSF 两种输入源选择方式都不控制输入法内部中英文状态。输入源失效时需重新选择，不自动安装或启用输入法。macOS 当前按用户配置选择系统输入源。

Windows 插件也可以要求切中文，由已保存的方案执行内部模式切换或布局选择。不支持就明确失败。macOS 的中文输入源、英文键盘布局需要在界面中明确选择，选项完整后自动保存，不自动安装、启用或猜选输入法。不做组字状态检测；主体不自动恢复各程序的历史输入状态。

配置修改自动保存，界面显示保存中、已保存或失败状态。方案未填完整时继续使用原方案，应用规则仍可独立保存；保存失败保留修改并提供重试，不会显示为已生效。

## 开发与运行

Windows 程序：`dist/ime-pilot.exe`，不需要随附 TSF DLL。依赖已缓存时，运行 `scripts/build-windows.ps1` 离线构建；需要已安装的 Wails CLI（`wails3`）将应用图标写入 EXE。Windows 使用纯 Go 调用系统 API，关闭 CGO，不需要 C/C++ 编译器，脚本不安装工具。当前实测 Windows x64，其他架构和应用兼容性以设备验证为准。

IDEA 插件在 Windows 上使用 `scripts/build-idea-plugin.ps1`，macOS 上使用 `scripts/build-idea-plugin.sh`，安装包为 `dist/ime-pilot-idea-0.4.1.zip`。插件在窗口聚焦及 IdeaVim 退出 Insert 时请求切英文。

Windows 联调时从资源管理器启动主程序。由 MSIX 打包应用启动的子进程可能继承 AppData 重定向，使主体和 IDEA 看到不同的 `runtime.json` 位置。

Windows + 微软拼音实测：不勾选 IDEA 应用规则时，插件仍可在聚焦及退出 Insert 时切英文；停用插件后，下一次聚焦恢复已启用的应用规则。

缺少环境或需要下载依赖时，先与使用者确认；环境变量只临时设置，不修改系统配置。

## macOS 开发与运行

需要 Go 1.26 或更新版本、Xcode Command Line Tools，支持在 Apple Silicon 和 Intel Mac 上构建本机架构版本。macOS 最低目标版本为 11.0，实际支持情况以设备验证为准。

```bash
# 已有依赖时离线构建；不运行单测
GO="$HOME/sdk/go1.26.8/bin/go" scripts/build-macos.sh

# 首次下载依赖需使用者确认，再显式开启
GO="$HOME/sdk/go1.26.8/bin/go" scripts/build-macos.sh --download-dependencies

open dist/ime-pilot.app
```

省略 `GO` 时使用 PATH 中的 Go。脚本只在自身进程内设置构建环境，缓存放在 `.tmp`，不会修改默认 Go 或系统环境变量。产物使用本地 ad-hoc 签名，未做 Developer ID 签名或公证，不是对外分发安装包。

首次运行：

1. 在“切换方案”中选择“系统输入源切换”，再选择已启用的中文输入源和英文键盘布局，配置完整后自动保存。如果列表里缺少所需输入源，先在系统设置 → 键盘 → 文本输入中添加，再重新进入“切换方案”页面，列表会自动更新并保留尚未填完的选择。
2. 打开“测试与诊断”，点击切换，在测试框核对候选与实际输入。接口确认的是输入源 ID，第三方输入法可能保留内部英文状态，选中中文输入源不等于强制恢复其内部中文状态。
3. 添加正在运行的应用，设置进入应用时切中文或切英文（无需切换时停用规则），确认自动保存成功后切到其他应用再切回来验证。
4. 关闭设置窗口后继续常驻；点击菜单栏图标打开设置、暂停/恢复或退出。

配置保存在 `~/Library/Application Support/ime-pilot/config.json`，单实例锁也在同目录。普通应用规则通过 NSWorkspace 监听应用激活，通过 TIS 选择系统输入源，不需要辅助功能或屏幕录制权限；IDEA 插件请求也只通过 NSWorkspace 校验前台应用 PID，不需要这些权限。两条路径均不读取窗口标题、输入文字或按键。

## macOS 适配进度

已实现：

- 复用 Wails 设置界面，增加 macOS 入口、菜单栏常驻、暂停和单实例管理。
- 按系统读取的 Bundle ID 枚举运行中的应用、持久化规则并在应用激活时执行。

- 提供 `.app` 构建、Info.plist 和本地签名脚本。

## macOS IDEA 插件

适配 IDEA build 261 / 262，IdeaVim 2.47.3 / 2.48.0；本机编译环境为 IDEA 2026.2 + JBR 25 + IdeaVim 2.48.0。没有 IdeaVim 时，仍可处理 IDEA 窗口聚焦。

```bash
scripts/build-idea-plugin.sh

# IDEA 或 IdeaVim 不在默认位置时
IDEA_HOME="/path/to/IntelliJ IDEA.app" \
IDEAVIM_HOME="/path/to/IdeaVIM" \
scripts/build-idea-plugin.sh
```

脚本复用已安装 IDEA 的 Java 编译器模块和依赖，不下载、不运行单测、不安装插件；输出 `dist/ime-pilot-idea-0.4.1.zip`。Windows 构建脚本仍使用原来的 IDEA 261 / IdeaVim 2.47.3 环境。

安装与联调：

1. 退出旧版主体后重新打开新构建的 ime-pilot，配置英文输入源（例如 ABC），确认自动保存成功。
2. 无需授予辅助功能权限；旧版本已授予的权限可以在系统设置中关闭，不影响当前实现。
3. 在 IDEA 的 Settings → Plugins → 齿轮 → Install Plugin from Disk 中选择上述 ZIP，按 IDE 提示完成加载或重启。不会修改 `.ideavimrc`。
4. 等待主体显示插件已连接，再通过新的 IDEA 窗口聚焦、IdeaVim Insert → Normal 验证英文切换；连接成功本身不会补切。
5. 在请求期间切到其他应用，确认旧请求不会继续切换；暂停应同时阻止插件和普通规则，卸载插件后下一次激活恢复普通规则。同一 IDEA 进程内的窗口切换不由主体区分。

实现边界：macOS 插件只发送进程 PID，主体通过 `NSWorkspace.frontmostApplication` 校验前台应用，并保留接管范围、应用激活代次、300 ms 排队过期和执行超时检查；不查询其他应用的窗口，不使用 AX API 或未公开窗口映射。插件本地焦点事件仍会作废未发出的请求，但请求发出后，同一 PID 内切换窗口可能让旧请求作用于新窗口，这是按进程校验的已知边界。Windows 仍发送并核实 PID 与 HWND。插件状态保留最近一次切换结果或错误，成功续期不会覆盖它，连接或暂停状态变化时更新。

## 代码架构

代码按核心、接入、系统信号和切换方案组织，由 `internal/bootstrap` 显式组装。接口、配置结构与验证边界见 [架构交接](docs/architecture-governance.md)。系统专有调用统一放在 `internal/platform/windows` 和 `internal/platform/darwin`，供方案、信号接入和基础设施复用；平台包不依赖核心或 UI，方案负责切换策略和结果验证。

设置界面从方案提供的表单生成配置项；Windows IMM 与 macOS 输入源方案各自拥有实现、配置校验和 UI 描述。Windows 构建脚本默认不运行单测，只有显式传入 `-RunTests` 才运行。

Windows IMM 兼容性限制（2026-10-31 实测）：豆包输入法 0.9.3.20 在主程序测试框中双向切换均未实际生效，尽管 IMM 转换模式回读变为 `0x0` / `0x1` 并显示成功。资源管理器中也出现实际为中文、回读为英文，导致英文应用规则误判“已是目标模式”。豆包自身 Shift 切换正常；当前 IMM 方案不能据回读结果宣称支持豆包。测试文字和临时规则已清理，原配置已恢复。

Windows 纯 Go TSF 实测（2026-10-31）：移除自建 DLL 后，豆包 0.9.3.20 与微软拼音独立枚举及配置保存、豆包与美国英语布局手动互切、豆包与微软拼音互切、资源管理器规则双向切换通过；通过真实按键、候选窗口及中文上屏核对效果，没有回读目标线程的 TSF 身份。单独调用 TSF 桌面激活不能可靠切换目标窗口的输入语言，因此实现配合了目标窗口语言切换。测试后恢复原配置。未验证提权应用、其他架构和第三方输入法；不代表支持豆包内部中英文状态控制。
